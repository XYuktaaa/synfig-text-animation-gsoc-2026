Per‑Character Text Animation

Google Summer of Code 2026 · Synfig Studio

A Text Group previously moved as one rigid block. This project gives every glyph inside it independent rotation, scale, and timing — and a mechanism for one glyph's animation to be shared with the rest, delayed, reordered, or reshuffled by a repeatable seed.

for users

Users Guide

A Text Group turns typed text into a small company of glyph layers, each one still under the Text Group's direction. What follows is how to give those glyphs their own motion, and how to hand that motion to one another.

What is a Text Group?

One text object becomes a managed collection of glyph layers, while a single Text Group parent still controls layout, font, and color. The glyphs live inside its subcanvas as implementation children — you don't create them directly, and they aren't meant to be treated as ordinary top‑level layers.

Making your first per‑character animation

  1. Create the text. Add a Text Group, type HELLO, and set its font, weight, size, and layout as usual. The Text Group shapes the text and builds glyph layers in its internal subcanvas.
  2. Select a glyph. Pick one letter — say, the H — and animate its Scale from 1.0 up to 1.3 and back. Rotation, Scale, and Animation Offset are all exposed as glyph‑level parameters. The Text Group's own origin stays separate and shouldn't be treated as a shared parameter.
  3. Open Share Animation. In the Text Group's Share Animation list, add an entry and choose Scale from the parameter selector — the custom picker built for this purpose, so you're choosing a glyph parameter rather than hunting through value‑node internals.
  4. Set delay and order. Delay controls how far each glyph is shifted in time from the source animation; order decides which glyph gets the earliest part of it. Forward order moves E‑L‑L‑O in sequence after H.
  5. Preview, then save and reopen. Confirm the same list, delay, order, and resulting animation come back exactly as you left them.

Sharing an animation, in plain terms

A source animation lives on one glyph's parameter. When you share it, the Text Group resolves that animated value node and connects it — through a per‑glyph time wrapper — to the same parameter on other glyphs. Delay is how far apart each glyph samples it; order is who goes first. A positive delay should always mean a later glyph starts later, not earlier — a wave forming rather than every glyph twitching at once.

Order

Forward

Proceeds through the glyph sequence, first to last.

Reverse

Starts from the last glyph and moves backward.

Random

Uses the Text Group's stagger seed for a repeatable shuffle.

The seed changes the random ordering without touching the animation itself — a way to try several controlled variations of the same effect. Change the seed, and the order reshuffles; keep everything else the same.

Choosing a parameter

Rotation, Scale, and Animation Offset are the glyph properties intended to be shared. Editing a shared parameter moves every glyph that participates in that sharing relationship — that's the point of sharing, not a side effect. Anything that needs to stay independently positioned shouldn't be shared.

Stagger recipes

Three starting points, served the way the Hatter would insist on serving them — with a cup for each mood.

Typing / Reveal

Delay small, steady step
Order forward

Pulse / Wave

Delay moderate
Order forward

A ripple moves through the word, rather than a single beat.

Random Chaos

Source rotation or scale
Delay your choice
Order random, with a seed

Unpredictable, but repeatable — change the seed to reshuffle it entirely.

Editing and undo

Removing a sharing entry restores the glyph's original, independent node rather than leaving a dangling connection. Add, edit, or remove entries and Synfig's action system carries the undo/redo — including the first entry you ever add, which is worth testing on its own.

Timeline advice

Stagger adds time to the sequence. If the source animation lasts T and there are N glyphs with a per‑step delay of d, the last glyph can need roughly T + (N−1)d to finish. Leave enough timeline after the source animation for the whole staggered sequence to land — the final letter is often still moving after the first one has stopped.

Saving

Sharing is stored as part of the document through Synfig's value‑node and canvas machinery — not a temporary Studio‑only setting. Before you call a scene finished: create a share, save, close, reopen, and check that the list, delay, order, and animation are exactly as you left them.

implementation workflows

What actually happens under the hood

These are the four paths that matter most when reading or maintaining Layer_TextGroup. They complement the high-level cards above rather than replacing them.

Workflow A · Text → glyph layers (sync_glyphs)

Text edits rebuild only what has to change.

load_font_static→ shape_text→ glyph contours + layout→ LCS match→ reuse / create GlyphShape

When text or font parameters change, sync_glyphs() loads the font, shapes the text (using HarfBuzz when available), converts each outline to contours, and computes glyph placement. The important preservation step is an LCS diff between old and new glyph identities: matching Layer_GlyphShape children are reused, so attached animation is not discarded just because the text changed. Glyph descriptions carry an identity key of the form cluster_<c>_glyph_<g>, which can be parsed back during synchronization.

Workflow B · Sharing + staggering

One source animation becomes many time-shifted samples.

UI staging params→ share_param→ resolve + export node→ SharedEntry→ TimeOffset per glyph

The Add Shared Animation UI stages param_stagger_delay and param_stagger_order; committing through param_share_target calls share_param(). The source glyph's animated node is resolved and exported under a persistent unique ID, then every participating glyph receives its own ValueNode_TimeOffset wrapper around that shared node.

For RANDOM order, rebuild_stagger_permutation() ranks glyphs from a hash of (cluster, glyph_index) mixed with a per-layer salt. Sorting those ranks produces stagger_perm_, so the order looks random but remains reproducible for the document.

Use your ownership/wiring diagram here: Layer_TextGroup, sub-canvas, shared_entries_, stagger_perm_, and the individual Layer_GlyphShape children.

Workflow C · Persistence and reconstruction

The relationship survives closing and reopening the document.

SharedEntry→ encode_shared_entry→ share_animations param→ reload + rebuild→ reattach

Sharing metadata is serialized through the single param_share_animations string. Each entry records target parameter, delay and order. On load or parameter change, rebuild_shared_entries_from_param() parses the structural data, reuses live node handles where possible, resolves new entries, severs relationships that disappeared, and reattaches the current set.

Workflow D · Runtime time evaluation (set_time_vfunc)

Staggering is evaluated as time, not duplicated keyframes.

group time→ dilation + offset→ base_time→ glyph layer→ TimeOffset wrapper

set_time_vfunc() first applies the Text Group's own time dilation and offset, then propagates that base_time to glyph layers in the sub-canvas. The per-glyph ValueNode_TimeOffset wrappers shift sampling by the stagger delay, which is why the implementation can reuse one underlying animation rather than copying its keyframes for every glyph.

Ownership

Layer_TextGroup owns text‑level state and the glyph subcanvas — when text or layout changes require synchronization, sharing bookkeeping, and applying shared relationships. Layer_GlyphShape owns the glyph's contour data and its per‑glyph parameters; it's an implementation layer, not meant for direct top‑level use. AnimShare / ValueNode_AnimShareList own the persistent sharing configuration. ValueNode_TimeOffset owns temporal sampling. Studio owns UI and actions.

Layer_TextGroup — key methods

on_canvas_set()

Initializes or reconnects the share_animations parameter and rebuilds sharing state when the layer attaches to a canvas.

set_param()

Separates structural text/layout changes (full resync) from lighter ones — kerning triggers a glyph sync, color updates child glyphs without rebuilding geometry, and a stagger‑seed change rebuilds the permutation.

sync_glyphs()

The central structural synchronization path — where text and layout changes become actual glyph layers.

get_shareable_params()

Reads the source glyph's dynamic parameter list — the basis for the Studio selector and for validating a requested share.

share_param()

Validates a parameter, resolves and exports its source node, creates a SharedEntry, and attaches wrappers.

unshare_param()

Removes the bookkeeping entry before detaching glyph wiring — ordering matters, since detach logic can re‑trigger attachment.

resolve_and_export_node()

Reuses an already‑wired shared node when one exists; otherwise exports the source glyph's node into the subcanvas under a persistent ID.

attach_shared_entries()

Applies every sharing entry to every glyph — computing the ordered time offset, reusing cached wrappers, and preserving pre‑share nodes.

find_wired_shared_node()

Finds a TimeOffset‑wrapped source node already wired to a glyph — used when reconstructing sharing from a loaded document.

apply_shared_entries_from_items()

Converts serialized AnimShare items into internal bookkeeping, reusing old caches where possible and detaching entries that disappeared.

Synchronization & preservation

The early prototype cleared the entire glyph subcanvas on every text change — destroying any hand‑made animation or connection in the process. The current model tracks existing glyphs and reuses them instead. Before a parameter is replaced with a TimeOffset wrapper, its original node is captured in pre_share_nodes, so unsharing can restore it. If the shared source node itself disappears mid‑edit, the affected entry is marked invalid rather than silently left dangling.

Studio & actions

Widget_ValueBase recognizes the anim_share_param hint and delegates to Widget_Sublayer, which builds the selector from the surrounding layer context. CanvasTreeStore was adjusted to preserve parent ValueDesc context so that selector can find the Text Group and its glyph parameters. Sharing edits route through Synfig's action system rather than direct mutation — direct mutation alone doesn't produce a coherent undo step. Unshare ordering matters here too: remove the bookkeeping entry first, or a reattach can immediately recreate what was just removed.

Two bugs, and how they were actually fixed

case study

Animate‑mode insertion crash

What happened — Inserting the first AnimShare entry while Animate mode was active crashed. The smart dynamic‑list insertion path prepared an ActivepointSetOff against a list that was still empty, because the insertion action hadn't executed yet — index 0 pointed at nothing.

The fix — AnimShareList membership is structural, so it bypasses the normal animated‑list activepoint handling. ValueNodeDynamicListInsertSmart gained a narrow special path that performs the ordinary structural insertion and returns before the generic activepoint logic runs — deliberately narrow, since other dynamic‑list types still need the normal animated behavior.

case study

Frame‑dependent sharing bug

What happened — An earlier implementation reconstructed sharing by evaluating the dynamic list at the current animation time. A structural sharing entry could vanish simply because the current frame didn't consider it "active."

The fix — Sharing membership is structural, not time‑dependent — reconstruction now reads the raw AnimShareList entries directly instead of asking the animated list for its time‑dependent active subset. New entries carry empty timing information on creation, so a share behaves identically whether the user is on frame 0 or frame 400 when the list is edited.

Extending it — adding a new shareable parameter

  1. Identify the GlyphShape parameter you want to expose.
  2. Verify it's safe to wrap in ValueNode_TimeOffset.
  3. Expose it through the Studio selector.
  4. Test inverse/editability if the parameter needs canvas editing.
  5. Add serialization and undo tests before calling it done.

Known failure signatures

  • Share disappears at a non‑zero frame
  • First AnimShare insertion crashes in Animate mode
  • Shared Scale can't be dragged in the canvas
  • Animation Offset fails composite inversion
  • Last staggered glyph doesn't finish before the timeline ends

honest accounting

What this isn't, yet

Claims this documentation deliberately avoids making, until they've been verified.

  • Universal script support isn't claimed just because HarfBuzz is present — only scripts that have actually been tested are described as supported.
  • A rendering‑speed improvement isn't claimed from the anecdotal observation that older animations looked smoother after Studio integration. That's useful validation, not a benchmark.
  • Animation Offset canvas editing isn't described as fully solved until Vector/Composite inversion is verified.
  • A staggered animation finishing at the source animation's end time isn't assumed — the final glyph may still be in flight, and any demo timeline needs to include that tail.
  • A new global stagger architecture wasn't introduced late in the project — the design intentionally keeps per‑entry delay/order plus a single Text Group seed.
